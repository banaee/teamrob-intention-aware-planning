# T-K part 1, step 5b: the planning set with context knowledge on (kitting, the working robot)

The records: design_records.md, "T-K", STEP 5B, PLANNED and the step's entries after it. A basic check, not a coverage
set. Results: `REPORT.md` (stage 3).

**The state the set meets.** The setups (env_setup_10 to _12) and the scenarios state no timeline, and the rooms
(env_layout_12 to _14) hold no A/C switch; env_layout_13 holds no coffee machine either. With context knowledge on,
only the state with no raising fact occurs: coffee_break has the ordinary strength 0.02 (0.005 for the 90 ticks after
an observed coffee break), the assigned tasks as a whole 1. With two deliveries live each has a prior of 0.49; with
one, 0.98. In scenario_s10_11 (env_layout_13) there is no foreseeable task, so the prior equals off's.

## The set

- The sixteen scenarios of the MPB as they are: scenario_s10_01 to _11, s11_01 to _03, s12_01, _02; their authoring:
  `analysis/kitting/mpb/README.md`, `authoring.md`, `coverage.md`.
- One strategy, single_task: every coverage case of the set is claimed under it (coverage.md: every instance is (S)
  or (S, F); none needs full_reorder).
- The reference (context knowledge off): `configs/kitting/mpb/scenario_s1*.yaml`, outputs in
  `analysis/kitting/mpb/<scenario>/on_single_task/` ("on" is the instrument's name for assignment knowledge on). Rerun
  at HEAD into another folder before this step: every log, `.rec` stream, reference log and instrument output
  byte-identical to the committed ones (the drift check), 0 disagreements in all sixteen.
- The runs with context knowledge on: `configs/kitting/mpb/tk5b/` (the reference's run files with
  `context_knowledge: true`, nothing else changed), outputs in `<scenario>/on_single_task/` here.

Commands (from the repo root):

    analysis/instruments/mpb/run.sh kitting --expect -o analysis/kitting/mpb/tk5b configs/kitting/mpb/tk5b/*.yaml
    analysis/instruments/mpb/run.sh kitting -o analysis/kitting/mpb/tk5b configs/kitting/mpb/tk5b/*.yaml
    analysis/kitting/mpb/tk5b/read5b.py expect     # the preview (below)
    analysis/kitting/mpb/tk5b/read5b.py report     # the runs, off against on (REPORT.md)
    analysis/kitting/mpb/tk5b/read5b.py rows       # the coverage rows whose instances move (REPORT.md)

## The expectations (stage 1, committed before any run with context knowledge on)

- Parts 1 to 3 (MPB-1): the oracle's per-tick table with context knowledge on (`expected_ticks.json`), from the
  trajectory (byte-identical to the reference's in all sixteen). After each run, the chain assembled from it with the
  run's own no_current_task ticks is compared with the run: 0 disagreements expected in all sixteen.
- Part 4: the declared properties of `analysis/kitting/mpb/properties.py`, unchanged, read on the on runs. They were
  declared for the set as authored (context knowledge off); a property that fails with context knowledge on is a
  finding of this step, not a defect.
- The authored case per scenario: `read5b.py`'s CASES, one check function per scenario, applied to both sides. On the
  reference every case is reached (checked before any run).
