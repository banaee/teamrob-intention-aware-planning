# T-K part 1, round 1: the round without context knowledge (the IRB on env_layout_15, _16, _17)

The data and figures of this set (.json, .csv, .png) are not in git (Hadi, 2 October 2026); they are regenerated by the
run script below. The instrument is the shared IRB (`analysis/instruments/irb/`, its README; rules 1 to 23 in
`analysis/kitting/irb/README.md`), unchanged; one reporting script is added, `admission.py` (below).

What the round is (design_records.md, "T-K", CONTENT POINT 3, THE TESTS, KT3 and KT5): context knowledge is ruled and
not built. This round runs the human's scripts in the three T-K rooms in the IRB with the prior as it is today (equal
over the live hypotheses, the support restricted by assignment knowledge). It shows how well the movement alone
separates the tasks in these rooms, and it is the "off" side against which the runs with context knowledge are later
compared: when the mechanism exists, the timelines of context facts go into the setups (AM34) and the same scenarios
run again. No timeline form is invented here.

## The artefacts

- **Rooms.** env_layout_15 (the basic room), env_layout_16 (the dense room), env_layout_17 (env_layout_15 plus the A/C
  switch between shelf_1 and shelf_4); their geometry is in each file's notes.
  **Changed for this round (ccode, 3 October 2026, before any run):** env_layout_16 lost shelf_3 and shelf_4, the two
  south-east shelves outside the cluster. Reason: with five items over walks of about 950 cm the human's work did not
  fit below step 500 (the control needed 530 steps, the longest placement 655; moving all seven targets 250 cm north
  still left 517). The cluster, the room's purpose, is unchanged.
- **Setups** (one per room for now; the second, differing in its timeline, comes with the mechanism): item_i on
  shelf_i, all designated to the one kitting table. env_setup_13 (env_layout_15: item_1 to item_4), env_setup_14
  (env_layout_16: item_0 to item_2), env_setup_15 (env_layout_17: item_1 to item_4).
- **Scenarios** (`domains/kitting/scenarios/scenarios_s13.py`, `_s14.py`, `_s15.py`). The robot at (-400, 400) with an
  empty pool, observing only; the human starts at the table (0, 450), is assigned every delivery, delivers them in one
  order per room (15 and 17: item_3, item_2, item_1, item_4; 16: item_0, item_2, item_1), returns to the table and
  ends with the exit walk to corner_NE. The only variation is where one foreseeable task is placed:

  | MM (s13, s15) | MM (s14) | placement |
  |---|---|---|
  | 01 | 01 | none: the deliveries alone, the control |
  | 02, 03, 04 | 02, 03 | coffee_break after the first, second, third delivery (a delivery always stays live) |
  | 05, 06, 07 | 04, 05, 06 | coffee_break inside the second delivery: after the walk to the shelf; after the grasp; after the carry, before the place |
  | 08, 09, 10 (s15 only) | 07, 08 | ac_activation after the first, second, third delivery |
  | 11, 12, 13 (s15 only) | 09, 10, 11 | ac_activation inside the second delivery, at the same three gaps |

  The order was chosen so that the foreseeable task's neighbouring deliveries by bearing are live where it is placed:
  in 15 and 17 both of the coffee machine's after the first delivery, both of the A/C switch's after the first and the
  second; in 16 the coffee machine's neighbour shelf_1 and the A/C switch's neighbour shelf_2 after the first.
- **Run files**: `configs/kitting/irb/tk1/scenario_sNN_MM.yaml` (a subfolder, so `run.sh kitting` without arguments
  still runs only the earlier set): prior on, single_task, gate none, cost realized, separation stop off, test level
  0.05; steps by IRB.3b's rule (the last acknowledgement + 1 + 30).

## TODO-66's context weight is kept out

The present recognizer multiplies coffee_break by 2.5 from observation timestamp 500 on (`_context_weight`,
`LONG_SHIFT_THRESHOLD = 500`, the shift starting at step 0; the room temperature is the default 21, below the A/C
boost's 26, so the A/C boost never acts). Nothing in a scenario or setup reaches it, so the round keeps every run below
step 500: the longest run is 481 steps (s13_07, s15_07), so the last observed tick is 480; the oracle assumes ω = 1
(rule 15), and the comparison would show any tick where the weight acted. The room change above is what makes room 16
fit.

## The measure (`admission.py`)

KT3's measure: per true stretch, the first tick the true hypothesis's belief is at or above θ, the first tick the gate
clears with it leading ("admitted"; the idle robot asks admission at tick 0 only, so this is the gate per tick, as in
summary.py), the ticks from there to its pin on which the gate no longer clears for it (the retraction reading), and
the ticks on which the gate clears for another hypothesis. Run on `expected.csv` before the runs and on `actual.csv`
after them: `admission.py analysis/kitting/irb/tk1 <expected.csv | actual.csv> 0.75`.
